Machine Time

Work in machine time. Sign in human time.

Machine Time is the method I use to build with agents. It splits the work by clock. Human time is serial: one person setting direction, making judgments, and answering for the result. Machine time is parallel: agents producing research, drafts, code, and test runs side by side inside the same day.

The point is not raw speed. The point is control at production speed. Agents can expand the amount of work in motion. They cannot expand the amount of work I can honestly verify. The method keeps those two numbers from pretending to be the same.

Limits

Three things cap machine time

Machine time has three hard limits. They decide how much of it is usable.

Concurrency

How many agent lanes run at once. More lanes mean more work in motion, and more output competing for the same review. A lane is useful only if its output can be directed and checked.

Cost

What parallel work costs. Agent time is cheap compared with skilled human time, but cheap work can still be wasted. Credits spent solving the wrong problem are gone, and the review time spent discovering that is gone too.

Verification bandwidth

How much output one accountable person can inspect, test, and sign. This is the real ceiling. Generation can be bought by the hour. A signature cannot.

The bottleneck

Many lanes in. One signature out. Production widens. Accountability does not.

Economics

The scarce part moved

Skilled human time used to be spent producing the work, so it was rationed with long plans and few attempts. Agent production changes where the ration sits. Drafts, research, and code are cheap to generate. Judgment is not. I spend human time before production on intent and after production on verification. Everything between those points has to earn its place by being checkable.

Cheap to generate

Drafts, code, and research can be produced in parallel at low cost. Low cost is not the same as low consequence.

Bounded by review

The usable amount of machine time is set by how much output can be inspected and signed, not by how much can be produced.

One signature

Every shipped change has one accountable person. Agents can recommend. They cannot absorb the risk.

The failure mode is not slow work. It is fast work aimed at the wrong target, or work produced faster than it can be checked. Machine Time treats speed as an input. The output is a change I can explain, test, and stand behind.

Workflow

The machine-time workflow

I run the same sequence each time. The order matters: intent before production, evidence before review, signature before release.

  1. Define the job.Human time Write the problem, what it affects, the constraints, what is out of scope, and the acceptance criteria. If done cannot be described, the work is not ready for agents.
  2. Split by clock.Human time Separate production from judgment. Agents take research, drafting, implementation, and test execution. I keep scope decisions, tradeoffs, and anything that changes the intent.
  3. Assign lanes with boundaries.Human time Each agent gets a bounded task, the files or sources it may touch, and the output I expect back. Parallel work without boundaries creates collisions and a larger mess to review.
  4. Produce in checkpoints.Machine time Work comes back in small pieces, with notes: what changed, what was assumed, and what still needs checking. A large silent dump is not accepted.
  5. Run the machine gates.Machine time Builds, tests, static analysis, and security checks run before human review. If a machine can settle a question, a machine settles it. Failures go back with the output attached.
  6. Review against the intent.Machine time A fresh-context reviewer compares the result with the intent and looks for mismatches: extra behavior, missing edge cases, weak tests, and claims the evidence does not support.
  7. Verify and sign.Human time I check the failure paths, confirm the tests prove the claim, and sign the specific change. If I cannot explain why it is safe to ship, it goes back.
  8. Ship contained and record it.Human + machine Release in small increments, behind a flag when the change calls for it, with monitoring and a rollback path. The record keeps the intent, the diff, the test output, the decision, and the known limits.

The Rule

The operating rule

Everything above reduces to one operating rule:

  • Work in machine time. Sign in human time.

Verification

Reviewing at machine time: the human in the loop

Review is the control point. I do not read every generated line, and I do not approve work I have not checked. The review follows a fixed order, so attention goes to fit, proof, and failure paths before style.

  1. Start with the evidence. A change arrives with the intent, the acceptance criteria, a plain summary of what changed, and the build and test output. If the evidence is missing, the review stops and the work goes back.
  2. Clear the machine checks. Build, tests, lint, static analysis, and security scans pass before I spend attention. A warning that does not block is noise: fix it or remove it, but do not train people to ignore it.
  3. Check fit before detail. The first question is whether the work solved the stated problem without adding behavior nobody asked for. If the fit is wrong, line-level review is wasted time.
  4. Inspect the failure paths. I read the parts that handle errors, permissions, data movement, and recovery closely. Happy paths are easy to generate. Failure paths show whether the work was understood.
  5. Audit the proof. Tests have to prove the acceptance criteria, not just pass. The agent that produced the work does not weaken, delete, or rewrite tests to make its own output look correct.
  6. Sign the exact change. Approval names the change being shipped. It is not approval of the agent, of the approach in general, or of the next change. If the record does not support the signature, the signature does not happen.

This is how the human stays in the loop without becoming the bottleneck for every line: machines clear what they can prove, an independent review hunts for mismatch, and I sign only what the evidence supports.
